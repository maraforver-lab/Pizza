# Patch 476: Public Metadata, Social Sharing and App Icon Audit

Type: read-only audit  
Starting commit: `d00f2d85960884e39106d2b176402a6c55f153d8`

Production changes: none

## 1. Executive Summary

DoughTools has a centralized SEO metadata system, but it is not ready for public indexing or polished social sharing yet.

Current production status:

- Production is not indexable.
- `/robots.txt` disallows all crawlers.
- every checked production route returns `X-Robots-Tag: noindex, nofollow, noarchive`.
- checked public routes include `meta name="robots" content="noindex, nofollow, nocache"`.
- public routes use clean `https://www.doughtools.app` canonical URLs when they have route metadata.
- sitemap contains 24 clean public URLs and excludes private, dynamic account/admin/API, and query-string URLs.
- no structured data / JSON-LD is currently implemented.

Main issues:

1. WhatsApp/social sharing uses the current global generated `/opengraph-image`, which is visually generic and carries older product-positioning copy: "Better pizza starts before the oven." It does not reflect the current polished product identity or route-specific content.
2. The social image route is cached as immutable for one year, and most routes expose the unversioned `/opengraph-image` URL. That makes social cache invalidation weak.
3. App/home-screen icons rely only on `/icon.svg`; there are no PNG app-icon derivatives, no `favicon.ico`, no `apple-touch-icon.png`, and no maskable Android icon.
4. Google indexing must not be enabled yet. Several workflow/token/private routes currently rely on the global pre-launch noindex shield rather than explicit route-level noindex/robots protection that will remain correct after `ALLOW_INDEXING=true`.

Decision:

- **GO for Patch 476A metadata/icon implementation.**
- **NO-GO for enabling Google indexing until Patch 476A is implemented and verified.**

The exact current social image is generated by `app/opengraph-image.tsx`:

- format: PNG
- dimensions: 1200 x 630
- production size: 56,282 bytes
- cache header: `public, immutable, no-transform, max-age=31536000`
- visual/copy content:
  - DoughTools wordmark
  - "Better pizza starts before the oven."
  - "Recipe, shopping, timeline and kitchen guidance for your next pizza night."

Root-cause assessment:

- The current source of the outdated WhatsApp preview is the global generated OG image at `/opengraph-image`.
- It is not route-specific and does not use the current homepage hero, current product screenshots, or a current dedicated brand-sharing asset.
- The long immutable cache header means social platforms can retain the image aggressively.
- Most routes expose the unversioned `/opengraph-image`; the homepage OG tag has a Next-generated hash query, but the Twitter tag still uses the unversioned URL.
- If WhatsApp shows the exact generated card described above, current production metadata is the root cause.
- If WhatsApp shows an even older image/copy, platform caching is probably an additional layer, but it is not the only issue because the current source image is itself stale/generic.

## 7. Home-Screen Icon Root Cause

Home-screen/bookmark/install behavior is inconsistent because every platform is pointed at one SVG.

Root causes:

- `app/layout.tsx` sets both normal icon and Apple icon to `/icon.svg`.
- `app/manifest.ts` exposes only one SVG manifest icon.
- no PNG Apple touch icon exists.
- no 192 x 192 or 512 x 512 Android/PWA PNG exists.
- no maskable icon exists.
- standard fallback paths such as `/favicon.ico` and `/apple-touch-icon.png` return 404.

If a device shows outdated or incorrect artwork, it can come from:

- the current only-source `/icon.svg`
- previous home-screen cache on the device
- platform fallback because Apple/Android do not receive the preferred PNG derivatives

The site should not depend on SVG-only app icons for launch.
